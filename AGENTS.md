# Repository Technical Language

Comprehensibility and technical assessability are first-class requirements.

For technical repository material, use the `technical-language-pass` skill. Its required order is technical completeness, `technical-english`, `style-pass`, then final technical review.

Write for a strong computer-science undergraduate unless a file targets specialists. State important results before their detailed machinery. Explain non-obvious reasoning, assumptions, invariants, and implementation-to-mathematics correspondence. Explain specialist techniques locally instead of relying on citations for essential understanding. State important correctness and complexity guarantees explicitly, with their assumptions and size parameters.

Comments must explain intent and reasoning, not obvious syntax. Keep comments and documentation synchronized with the implementation.

For academic manuscript prose, use `style-pass` by default unless the user requests the full technical-language workflow.
